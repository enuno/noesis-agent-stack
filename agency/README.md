# agency/ — Agency Catalog Integration (Tier A control plane)

Two-tier integration of the [Agency agent catalog](https://github.com/msitarzewski/agency-agents)
(MIT, pinned in `SOURCE`) into the Noesis Hermes fleet. Consensus plan:
`.omh/plans/ralplan-agency-integration.md`.

## Layout

| Path | Role |
|------|------|
| `SOURCE` | Pinned upstream URL + commit hash. Bump only via repin procedure below. |
| `LICENSE`, `ATTRIBUTION.md` | MIT license copy + attribution record. |
| `curation.yaml` | The 18-agent Tier A curation (1 per division, wave 1 = 8, wave 2 = 10). Sole roster source for everything downstream. |
| `convert.py` | Spec generator. Modes: `--preview <slug>`, `--promote <slug>`, `--full-tree`, `--check`. Emits `agents/<profile>/{SOUL.md,agent.yaml}` plus `integrations/prefer-live.yaml`. |
| `validate-specs.py` | Three-layer reviewer-guard (curation / generated specs / apply-layer static checks) + description-uniqueness (TF-IDF cosine, fail > 0.85). |
| `integrations/hermes-plugin/` | Vendored lazy-router plugin (generated by upstream `build-hermes-plugin.py`; byte-compare on `--check`). |
| `integrations/prefer-live.yaml` | Prefer-live overlay: deterministic pre-ranking so router candidates matching a live Tier A profile are suppressed unless `router_exploration` is set. |
| `.scratch/` (gitignored) | On-demand generated Tier A specs (`--full-tree` / `--promote`). **Never commit.** |

## Operating rules

1. **Tier A is capped at 18** (one per division). Expanding past 1/division
   requires a recorded routing smoke test first (`ROUTING-SMOKE.md` outcome +
   validator cosine < 0.85).
2. **All Tier A profiles are advisory-only**: `reports_to: noesis-core`, no
   privileged tools, no secret access, no autonomous execution; production /
   credential / financial actions require human approval.
3. **Tier A specs are generated, not committed.** Live materialization is
   done exclusively by `scripts/apply-agency-profiles.sh` (Phase 2); Ansible
   (Phase 3) invokes that script rather than materializing specs itself
   (single materializer — no dual paths).
4. **Secrets**: no secret-bearing fields may appear in `agent.yaml` or
   `SOUL.md`. Two-layer scan: `validate-specs.py` (hard fail) + the apply
   script's runtime assertion (Phase 2).
5. **Repin procedure**: update `SOURCE` commit → run
   `python3 agency/convert.py --check` → run
   `python3 agency/validate-specs.py` → re-vendor plugin → commit the pin
   bump with the upstream compare link. If `--check` reports content drift
   in any curated persona, the repin is blocked until curation.yaml
   rationale entries are re-confirmed.

## Quick start (pre-apply, local verification only)

```bash
python3 scripts/check-agency-names.py          # curation sanity vs pinned tree
python3 agency/convert.py --full-tree          # generate specs into .scratch/
python3 agency/validate-specs.py               # three-layer guard + cosine
python3 agency/convert.py --check              # pin + drift + secret scan
```

Applying to `~/.hermes/profiles/` is Phase 2 and gated behind the B2 commit
review (operator sign-off of `curation.yaml`).
